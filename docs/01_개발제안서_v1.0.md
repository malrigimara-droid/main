# 리가메디 WOS 고도화 개발 제안서
**버전** v1.0 · **작성일** 2026-05-27

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 리가메디 WOS(Web Order System) 고도화 |
| 대상 사이트 | ligamedi.mycafe24.com (WOS), ligamedi.com (메인) |
| 플랫폼 | 카페24 기반 확장 |
| 목표 | 재고 수집 → 주문 제안 → 승인 → 진행 추적 4단계 전체 자동화 |
| 파일럿 병원 | 경희채움정신과 |

---

## 2. 현재 문제 / 자동화로 해결할 것

| 현재 방식 | 고도화 후 |
|---|---|
| 담당자가 수기로 재고 파악 | 병원 PC 에이전트가 매일 22:00 자동 수집 |
| 엑셀로 발주량 계산 | 안전재고 공식 + AI 에이전트가 자동 제안 |
| 발주서 수동 작성 → 팩스/이메일 전송 | 병원 승인 1회 → 신성아트컴 CSV 자동 전송 |
| 배송 상태 유선 확인 | 단계별 카카오톡 자동 알림 + 웹 추적 화면 |

---

## 3. 시스템 아키텍처

```
[병원 PC]
 이지스 재고 DB
      ↓ (에이전트 22:00 자동)
[api.ligamedi.com]  ←→  [ligamedi.mycafe24.com/wos]
      ↓                         ↓
  재고 DB 저장            병원 담당자 웹 대시보드
      ↓
  AI 에이전트 (Claude API)
  안전재고 공식 계산 + 추세 반영
      ↓
  병원 담당자 승인
      ↓
  신성아트컴 CSV 자동 생성·전송
      ↓
  진행 상태 업데이트 → 카카오톡 알림
```

## 4. 화면별 개발 명세

### Screen 1 · 원내 에이전트 (병원 PC 트레이앱)

**목적**: 이지스 재고 데이터를 리가메디 서버로 자동 전송

**컴포넌트**

| 요소 | 상세 |
|---|---|
| 연결 상태 표시 | 초록 점(정상) / 빨간 점(오류) + 원격 점검 트리거 |
| 자동 수집 일정 | 기본 매일 22:00, 설정에서 변경 가능 |
| 마지막 전송 이력 | 날짜·시간·전송 품목 수·처리 결과 |
| 전송 범위 체크박스 | 약품 재고(수량·lot·유통기한), 처방 통계(환자정보 제외) |
| 수동 전송 버튼 | 발주 직전 즉시 점검용 |
| 전송 이력 버튼 | 최근 30일 전송 로그 조회 |

**기술 방향**
- Python + PyInstaller 또는 Electron (Windows 트레이 앱)
- 이지스 DB 직접 쿼리 또는 이지스 내보내기 파일 파싱
- HTTPS API 전송 (api.ligamedi.com)
- PIPA 대응: 환자 식별 정보 필터링 후 전송
- v1.2 동의서 서명 전까지 전송 차단 로직

---

### Screen 2 · WOS 주문 제안 화면

**URL**: `ligamedi.mycafe24.com/wos/order-proposal`

**컴포넌트**

| 요소 | 상세 |
|---|---|
| 헤더 요약 | 기준일, 발주주기, 발주 예정 종수, 예상 금액 |
| AI 에이전트 알림 배너 | 공휴일 반영, 추세 반영 등 조정 근거 자동 표시 |
| 약품 테이블 | 약품명, 향정/변동큼 배지, 현재고, 안전재고, 일평균, ROP, 제안발주량, 수정입력, 메모 |
| 인라인 수정 | 수량 직접 수정 가능 (수정 시 배경색 변경) |
| 임시 저장 버튼 | 수정 내용 저장 후 나중에 재개 |
| 검토 후 승인 버튼 | 승인 확인 모달 → Screen 3으로 이동 |

**안전재고 공식**

```
ROP = (일평균사용량 × 리드타임) + 안전재고
안전재고 = Z × σ × √리드타임
제안발주량 = ROP - 현재고 (+ AI 조정값)
```

**AI 에이전트 역할 (Claude API)**
- 최근 4주 사용량 추세 분석 (+X% 증가 시 발주량 상향)
- 다음 주 공휴일 감지 → 보장기간 자동 +1일
- 계절성 패턴 감지
- 조정 근거 한국어 요약 → 배너에 표시

**배지 분류**

| 배지 | 조건 |
|---|---|
| 향정 (주황) | 향정신성의약품 품목 |
| 변동큼 (노랑) | 최근 4주 표준편차 > 평균의 30% |

### Screen 3 · 승인 완료 화면

**URL**: `ligamedi.mycafe24.com/wos/orders/{ORDER_ID}`

**컴포넌트**

| 요소 | 상세 |
|---|---|
| 성공 체크 아이콘 | 주문 전달 완료 메시지 |
| 5단계 진행 타임라인 | 병원 승인 → WOS 등록 → 신성아트컴 전송 → 출고 준비 → 택배 발송 |
| 주문 요약 카드 | 품목 수, 총 수량, 총 금액, 향정 포함 수, 알림 채널 |
| 알림 안내 | "진행 단계는 카카오톡으로 자동 알림" |

**자동화 동작 (승인 클릭 시)**
1. WOS DB에 주문 저장 (ORDER_ID 생성)
2. 신성아트컴 포맷 CSV 자동 생성
3. 신성아트컴 이메일/SFTP 자동 전송
4. 카카오톡 알림 발송 (KakaoTalk API)
5. 진행 현황 페이지로 링크 생성

---

### Screen 4 · 진행 단계 추적 화면

**URL**: `ligamedi.mycafe24.com/wos/tracking/{ORDER_ID}`

**컴포넌트**

| 요소 | 상세 |
|---|---|
| 주문 헤더 | ORDER_ID, 주문일시, 품목 수, 총금액, 현재 상태 배지 |
| 진행 타임라인 | 각 단계별 타임스탬프, 현재 단계 강조, 예정 시간 표시 |
| 택배 정보 | 택배사명, 송장번호 |
| 출고 명세 테이블 | 약품명, 주문수량, 출고수량, 상태(정상/부분/미출고) |
| 알림 배너 | 부분 출고건 약사 우선 알림 안내 |

**진행 단계 5단계**

```
주문 접수 → 출고 준비 → 출고 완료 → 배송 중 → 도착 예정
```

**카카오톡 알림 트리거**

| 단계 | 알림 내용 |
|---|---|
| 신성아트컴 전송 완료 | "[리가메디] 주문 ORD-XXXXXXXX 접수 완료" |
| 출고 완료 | "[리가메디] 출고 완료 · 송장번호: XXXX" |
| 배송 시작 | "[리가메디] 배송 출발 · 도착 예정: 내일 09~12시" |
| 부분 출고 | "[리가메디] 부분 출고 발생 · 약사 확인 필요" |

## 5. 기술 스택

| 레이어 | 선택 기술 | 이유 |
|---|---|---|
| 프론트엔드 | HTML/CSS/JS (카페24 스마트앱) | 카페24 플랫폼 호환, 빠른 배포 |
| 백엔드 | PHP 또는 Node.js (Express) | 카페24 스마트앱 지원 언어 |
| DB | MySQL (카페24 제공) | 별도 인프라 없이 바로 사용 |
| AI 에이전트 | Claude API (Anthropic) | 추세 분석·근거 한국어 생성 |
| 알림 | 카카오 알림톡 API | 병원 담당자 카카오톡 수신 |
| 에이전트 앱 | Python + PyInstaller | Windows 트레이앱, 단일 exe |
| 이지스 연동 | 내보내기 파일 파싱 (Excel/CSV) | 이지스 DB 직접 접속 없이 파일 감지·파싱 |
| CSV 전송 | SMTP 이메일 (1차) + 신성아트컴 API (2차) | 이메일 확정, API는 명세 확인 후 추가 |

## 6. 개발 단계 (Phase)

### Phase 1 · 기반 (3~4주)
- [ ] WOS DB 스키마 설계 (약품, 재고, 주문, 진행 상태)
- [ ] 카페24 스마트앱 등록 및 기본 라우팅
- [ ] 병원 로그인/인증 (병원별 다중 테넌트)
- [ ] API 서버 기본 구조 (api.ligamedi.com)

### Phase 2 · 재고 수집 (2~3주)
- [ ] 원내 에이전트 Windows 트레이앱 개발
- [ ] 이지스 DB 연동 또는 파일 파싱
- [ ] 재고 데이터 암호화 전송 API
- [ ] 수동 전송 + 전송 이력 화면

### Phase 3 · 주문 제안 (3~4주)
- [ ] 안전재고 공식 계산 엔진
- [ ] Claude API 연동 (추세 분석 + 조정 근거)
- [ ] 주문 제안 테이블 UI (인라인 수정, 배지, 배너)
- [ ] 임시 저장 + 승인 플로우

### Phase 4 · 발주 자동화 (2~3주)
- [ ] 신성아트컴 CSV 포맷 생성
- [ ] 이메일/SFTP 자동 전송
- [ ] 승인 완료 화면 + 타임라인
- [ ] 카카오 알림톡 API 연동

### Phase 5 · 진행 추적 (2주)
- [ ] 진행 상태 업데이트 API (신성아트컴 웹훅 또는 수동)
- [ ] 추적 화면 UI
- [ ] 부분 출고 처리 로직
- [ ] 전체 알림 흐름 테스트

## 7. 핵심 API 설계

```
POST /api/v1/inventory/push          # 에이전트 → 재고 전송
GET  /api/v1/order/proposal          # 주문 제안 목록 조회
POST /api/v1/order/proposal/save     # 임시 저장
POST /api/v1/order/approve           # 승인 → 자동 발주 트리거
GET  /api/v1/order/{id}/tracking     # 진행 상태 조회
POST /api/v1/order/{id}/status       # 진행 상태 업데이트 (신성아트컴 측)
POST /api/v1/notify/kakao            # 카카오 알림 발송
```
