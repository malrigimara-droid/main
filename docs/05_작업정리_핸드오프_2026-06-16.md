## 1. 확정된 아키텍처 (정정본)

```
[병원: 이지스]                        [리가메디]
  현재고                               SIMS (신성 ERP)
   │ ⓪ 수집 에이전트(RPA+반자동)         · 발주/매출/재고/마약류(NIMS)/KPIS 신고
   ▼                                    · NIMS 연계(API) 자동 보고 중
[카페24 산출 사이트]  ── 발주 ──▶  SIMS 매입/매출 엑셀등록
  현재고 업로드 → 안전재고 차이 산출        → 보고/출력 → 포장 → 택배
   │ 푸쉬 알림                            → 발송목록 + 송장
   ▼                                      ▼
[리가메디닷컴 WOS]  ←──────────  실제 발주수량·상태 보고
  (약사 직접 주문, 신성아트컴 제작, 유지)
```

**핵심 사실**
- **신성아트컴 = SIMS(리가메디 ERP)와 www.ligamedi.com(WOS) 둘 다 제작** → WOS↔SIMS 연동은 동일 벤더 내부라 용이.
- **리가메디닷컴 WOS = 유지**(약사 직접 주문 선호). **고도화 대상 = 카페24 "산출 사이트"**.
- 산출 사이트 핵심 = **현재고 업로드 → 안전재고 설정값과의 차이 산출(= 제안 발주량)**.
- **NIMS: SIMS가 이미 `연계(API)`로 자동 보고 중** (마약류 취급내역 보고 화면 확인). 매칭 소스로 격상 가능.

## 2. 핵심 설계 결정 (요약 + 근거)

| # | 결정 | 근거/메모 |
|---|---|---|
| 1 | **발주 = 상품(브랜드)별 독립이 기본** | 성분당 평상시 1브랜드 |
| 2 | **두 브랜드 동시 재고 = 전환/스위칭 구간뿐** | 클로나제팜 = 환인↔리보트릴 공급 따라 스위칭(혼용 아님) |
| 3 | 전환/스위칭: **두 재고 합산 vs 성분ROP → 전환 대상(active)으로 발주**, 나머지 발주중단·소진 | 양방향(↔) 가능 |
| 4 | **공급 재개 시 리가메디 마진 기반 재스위칭 추천** | 매입가(cost)로 마진 판단. 고마진 품절→저마진 밀린 경우만 추천, 반대는 유지권장. "리가메디 추천" 라벨·병원 수락/거절 |
| 5 | **2단 모델**: 발주=성분 맥락 / 재고·lot·유효기간·NIMS=상품·lot 특정 | 항상 상품·lot 분리 |
| 6 | 재고/유효기간: **완통/개봉은 반품·폐기 판단 시에만 실사(길①)** | 평소 부담 0 |
| 7 | 반품/양수양도/폐기 판정 자동 (일반=출고1년·완통 / 향정=양수양도·보건소폐기) | |
| 8 | **NIMS 매칭 = 사전대조 파수꾼**(대체 ✕), 불일치 8유형 | 매칭키 = 거래일+품목+lot+수량+거래처 |
| 9 | 이지스 수집 = **RPA(화면 자동클릭) 기본 + 반자동 1클릭 fallback** | 이지스사 동의 없음 → DB직접 불가. 환자정보 제외(PIPA) |

## 3. 만든 산출물

### 3-1. 프로토타입 `prototype/index.html` (목업·6화면)
- **⓪ 수집 에이전트** — 이지스 자동조작 5단계 시각화, 완료 시 ①에 반영, 자동화 실패→반자동 1클릭 팝업, 수집이력
- **① 주문 제안** — **현재고 CSV 업로드→안전재고 차이 산출**, ROP·향정/변동큼 배지, 안전재고·발주량 인라인 수정, 추가발주 직접입력, 전환·스위칭(+마진 재스위칭 추천)
- **② 승인 완료** — 5단계 타임라인, 주문 요약, 카카오 알림
- **③ 진행 추적** — 타임라인·택배/송장·부분출고 배너·출고 명세
- **④ 재고·유효기간** — 요약카드 5, 위험현황, 완통/개봉 실사 모달, 반품/양수양도/폐기 판정
- **⑤ NIMS 매칭** — 향정 전용, 매출↔양수 사전대조, 불일치 8유형, 보정(재보고) 요청

### 3-2. 실제 동작 사이트 v1 `app/` (Node/Express)
- **실동작**: 현재고 CSV 업로드 → 서버 파싱·매칭 → 안전재고 차이 산출 → 발주서 CSV 출력. 안전재고 설정 파일 영속.
- 구성: `server.js`(API) · `compute.js`(산출엔진) · `data/drugs.json`(약품 마스터) · `public/`(웹) · `test.js`(검증 통과)
- API: `GET /api/proposal`, `POST /api/upload`, `POST /api/settings`, `GET /api/order.csv`
- 실행: `cd app && npm install && npm start` → `http://localhost:3000`

## 4. SIMS 연동 지점 (실측)

| SIMS 메뉴 | WOS 연동 의미 |
|---|---|
| **매입/매출 엑셀등록** | WOS 발주서가 들어갈 지점 |
| **매출관리 + 마약류 신고관리** | NIMS 매칭의 "리가메디 매출보고" 소스 (연계 API) |
| KPIS 신고관리 | 의약품 공급내역(일련번호) 보고 |
| 재고관리 | 리가메디(도매) 재고 — 양수양도·반품 회수 |
| 거래명세서/세금계산서 | 출고·송장·정산 회신 |

**마약류 보고 실측 필드(매칭키 정답지)**: 취급일자·보고구분(구입/판매)·취급자식별번호·취급자명·제품표준코드·**제조번호(lot)**·중점일반구분·보고유형(신규/취소)·사용자보고식별번호.

## 5. 아이디어 / 추가 검토 항목 (마스터파일에 녹일 후보)

1. **발주서 SIMS 양식 자동 변환** — 매입/매출 엑셀등록 컬럼에 정확히 맞춰 1클릭 발주.
2. **다병원 확장(멀티테넌트)** — 경희채움 검증 후 리가메디 거래 병원 전체로. 병원별 로그인·안전재고 프로파일.
3. **유효임박 향정 양수양도 중개** — 한 병원의 완통 임박분을 다른 병원/리가메디로 매칭(폐기손실↓).
4. **AI 수요예측 고도화** — 계절성·요일·처방 추세·공휴일 반영(현재 ROP+α를 학습형으로).
5. **마진 최적화 발주** — 동일 성분 내 마진/공급안정/유효기간 종합 점수로 브랜드 추천(현 재스위칭 추천 확장).
6. **KPIS 공급내역 자동 대사** — 마약류(NIMS) 외 일반약 공급보고까지 사전 점검.
7. **월간 손실·반품 리포트** — 폐기/반품/로스 가시화(이론 vs 실사 차이).
8. **카카오 알림톡 단계별** — 접수/출고/배송/부분출고/재스위칭 권장 알림.
9. **캐니스터(자동포장기) 연동** — 전환 시 캐니스터 준비 알림·체크(현 경고 로직 확장).
10. **타 EMR 대응** — 이지스 외(의사랑 등) 수집 어댑터 구조화.
