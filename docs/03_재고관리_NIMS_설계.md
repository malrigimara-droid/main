# 리가메디 WOS 재고·유효기간·NIMS매칭 설계
**작성일** 2026-06-16 · 현장 인터뷰(경희채움 기준) 반영 · 제안서 v1.0 보강

> 스코프 철학: **필수만 건드린다.** NIMS는 공급자·수요자가 함께 쓰는 공식 시스템이므로 WOS는 이를 대체하지 않고 **"양쪽이 어긋나지 않게 지키는 파수꾼"** 역할만 한다. 유효기간 내 소진 가능성·반품/폐기 판정·양수↔매출 매칭이 핵심.

---

## 1. 재고 라이프사이클 (뼈대)

```
입고            보유             위험 감지              의사결정                    실행·증빙
lot·유효기간  → 이론재고·소진예측 → 소진<유효 위험 →  소진촉진/발주억제/반품/양수양도/폐기 → 반품 or 보건소폐기
(자동 수신)     (자동)             (자동 경고)         (판정 자동 + 약사 실사 확인)        + NIMS 매칭 점검
                                                     └ 향정 = 별도 법적 트랙 ┘
```
이 흐름은 **발주 제안 화면으로 역류**한다: 재고 과잉·유효 임박 → "발주 0/억제" 근거 배너.

## 2. 데이터 소스 (거의 자동, 수기 최소)

| 데이터 | 출처 | 비고 |
|---|---|---|
| 입고 lot·유효기간 | **신성아트컴 출고기록** | 리가메디 매출=병원 입고 |
| 사용·출고·재고 | **이지스** | 병원 EMR |
| 이론재고 (lot별) | Σ입고 − Σ사용 (자동 산출) | 두 소스 **교차검증**으로 오차 탐지 |

- 수기로 남는 것: ① **완통→개봉 전환** ② 정기 실사 보정 ③ 폐기 처리
- FEFO "이 통부터 까세요" 지정은 **이지스가 이미 수행 → WOS 중복 안 함**

---

## 3. 포장·완통/개봉 모델

- 품목별 **포장규격(통당 정수)** 마스터 관리. 규격은 자주 안 바뀜. 소포장(30T)/대포장(200T)은 **별도 품목코드**.
- 향정도 대포장·캐니스터 사용. 캐니스터엔 약 크기 따라 200~800정.
- **캐니스터 충전 = 개봉.** 캐니스터 잔량 = 원내(약국) 재고로 카운팅.
- 캐니스터 등록 여부는 빈도·사용자 결정 (모든 약이 들어가지 않음).

### 완통/개봉 추적 = 길① (확정)
- 평소엔 **이론재고만** 표시 (완통/개봉 실시간 구분 안 함).
- **반품/폐기를 판단하는 순간에만** 약사가 "완통 N통 / 개봉 M정" 실사 입력.
- 근거: 개봉 이벤트 기록이 현장에 없음. 반품·폐기는 상시가 아니므로 그 시점 실사가 현실적.
- 반품 가능의 본질 = **타 병원·약국으로 유통 가능한 상태(미개봉/완통) 보존**.

---

## 4. 반품 / 양수양도 / 폐기 판정 규칙

### 반품·양수양도 후보
| 구분 | 조건 | 결과 |
|---|---|---|
| 일반약 | 미개봉(완통) + **출고일 ≤ 1년** + '임박품 양해출고' 아님 | 반품 후보 |
| 향정 | 미개봉(완통) + **유효기간 잔여 있음** | 원 판매처(리가메디) **양수양도** 후보 |
| 개봉분 (일반·향정 공통) | — | **반품 불가 → 소진 우선** |

- 반품 1년 원칙엔 예외 있음: 리가메디가 **임박품 양해 출고**한 건은 출고 시 플래그 → 반품 판정에서 자동 제외.

### 폐기 (향정)
- 유효 경과 → **완통/개봉 불문 보건소 폐기** 대상 (통+정 전부 집계).
- 유효 **6개월 전**부터 "폐기 위험" 경고 → 소진촉진 / 완통+유효남음이면 양수양도 유도.
- 타임라인: `유효 6개월 전 경고 → (완통+유효남음→양수양도 창구) → 유효 경과 → 폐기 대상`

## 5. NIMS 양수↔매출 매칭 현황판 (향정 핵심)

```
리가메디 매출보고(누구에게·뭘·얼마나)  ┐
                                       ├─ WOS가 짝짓고 일치 검증 → 어긋나면 경고(보고 前 사전 대조)
병원 양수보고(누구한테·뭘·얼마나)        ┘
```
- **양쪽 모두에게 이득** = 보고 전 미리 맞춰 행정 리스크 제거(신뢰 장치).
- 매칭 키: 거래일자 + 품목 + **lot** + 수량 + 거래처 (+ 시점차 허용범위)
- 불일치 유형: 한쪽 미보고 · 수량 불일치 · lot 불일치 · 품목/코드 불일치 · 중복 · 지연보고 · 반품 역방향 · 폐기내역
- 경계: **NIMS 직접 입력·폐기 실행은 사람.** WOS는 사전 대조·경고까지만.

## 6. 우리가 안 하는 것 (스코프 경계)
- NIMS 대체/직접 보고 ✕ · FEFO 통 지정 ✕(이지스가 함) · 로스분 자동 카운트 ✕(이론 vs 실사 '차이'로만 가시화) · 반알 0.5정 강제 ✕(수동조제 트랙)
- 캐니스터 혼입분 = lot 추적 불가 구간으로 인정.

## 7. 성분 2단 모델 (2026-06-16 확정·구현)

동일약품 **2줄 vs 합산** 논의의 결론. 수요는 상품명이 아니라 **성분 기준**이다.

| 레벨 | 다루는 것 | 기준 |
|---|---|---|
| **성분(generic)** | 수요·ROP·안전재고·발주 제안 | 브랜드 무관 **합산** (예: 아빌리파이+아라빌 = 아리피프라졸 1줄) |
| **상품(product)·lot** | 재고·유효기간·반품·양수양도·폐기·NIMS | 브랜드·lot **특정** |

- 발주 제안량은 성분 합산으로 산출 → 한 성분에 상품이 둘 이상이면(듀얼코드/제조사 전환) **상품별 사용량(share) 비율로 배분**, "배분합 = 제안" 일치 검증.
- 듀얼코드/제조사 전환 = 별도 개념이 아니라 **"한 성분 라인에 상품 2개"**인 상태.
- 기본은 합산, 의사가 특정 브랜드를 지정하는 등은 분리 가능.
- 구현: `prototype/index.html` (① 발주 = 성분 합산행+상품 배분행, ④ 재고 = 상품·lot 분리행).
