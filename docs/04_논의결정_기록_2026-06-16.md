## 4. 재고 관리 — 현장 인터뷰 (핵심 설계 소스)

### A. 포장 단위
- 주로 통(병/박스)이지만 PTP도 다 있음. 통당 정수는 품목마다 다름(규격은 잘 안 바뀜).
- 같은 약 여러 규격 혼재 입고 없음. 단 30T(소포장)/200T(대포장)은 대부분 구분됨.
- 향정도 대포장 있음. 캐니스터엔 약 크기 따라 200~500정(많으면 800정).

### B. "개봉" 인지 ★
- **개봉 기록 자체가 없음.** 새 포장을 훼손/뜯어 캐니스터에 붓는 순간이 개봉(조제 준비과정).
- 반품 조건의 본질 = **타 병원·약국으로 유통 가능한 상태(미개봉/완통) 보존.**
- 캐니스터 800정까지 들어가 **여러 통 동시 개봉 가능.**

### C. 잔여 정 추적
- 실사 카운트. 향정 아니면 완벽 카운트 불가(법정관리 대상 아니라 오차 존재, 관리 잘 되는 곳은 작음).
- 반알 조제 있음(법적 가능 약물+의사 판단). 맞출 수 없음 → 캐니스터 불가, **수동조제**(추가 투입 장치).
- 손실분(분진·파손·시험포장): 잔량에서 빠지지만 자동 카운트 안 됨. 현장 최대 난점, 증명 어려워 감수.

### D. 통-lot-유효기간
- 한 통 = 한 lot = 한 유효기간. 맞음. **단 캐니스터에 섞어 부으면 추적 불가.**
- FEFO "이 통부터" 지정 → 실제론 맞지만 **이지스 등에 이미 있음 → 우리는 중복 안 함.**

### E. 반품 (일반약 + 완통 향정)
- 일반약: 명문 기준 없이 다 해주다가, **"출고 1년 이내" 원칙** 세우려 함. 단 무조건 아님(임박품 써달라 보낸 경우 등 예외).
- **부분개봉통 = 무조건 반품 불가.**
- **완통(미개봉) 향정 + 유효 잔여 → 원 판매처(리가메디) 양수양도 가능.**

### F. 폐기 (향정)
- 향정 개봉+유효경과 → 보건소 폐기. **향정 완통+유효경과도 폐기 원칙.**
- 경고: **유효 6개월 전**부터.
- 폐기 집계: 통+잔여 정 **전부**(재고 있고 유효 임박이면).

### G. 캐니스터
- 통을 캐니스터에 부으면 = **개봉으로 봄.** 캐니스터 잔량 = 원내(약국) 재고로 카운팅.
- 향정도 캐니스터에 들어감. 단 모든 약이 들어가는 건 아니고 빈도·사용자 결정.

### 데이터 소스 (사장님 확인)
- **통/정 + 완통/개봉 구분 추적 가능.**
- lot·유효기간·출고 데이터 → **이지스 + 신성아트컴 양쪽 보유** → 이론재고 자동·교차검증, 수기 최소.

## 5. 재고관리 설계 확정 (→ `리가메디_WOS_재고관리_설계.md`)
- **완통/개봉 추적 = 길①**: 평소 이론재고만, **반품/폐기 판단 순간에만 "완통 N통/개봉 M정" 실사 입력.** (평소 부담 0)
- 라이프사이클: 입고(자동) → 보유·소진예측(자동) → 위험감지(자동 경고) → 의사결정(반품/양수양도/폐기/소진) → 실행·증빙.
- 안 하는 것: NIMS 대체·FEFO 통지정·로스 자동카운트·반알 0.5정 강제.

**구현·검증 (재고·유효기간 화면 ④)**
- 요약카드 5개(유효위험·폐기·반품후보·양수양도·폐기손실), 위험 현황판, 자동 상태 판정.
- **길① 실사 모달**: 향정 폐기(보건소+NIMS)/향정 양수양도/일반 반품/출고>1년 반품불가 4분기 검증.
- 발주 화면에 재고 위험 배너(역류).

## 6. NIMS 양수↔매출 매칭 현황판
- **스코프 철학**: NIMS는 공급자·수요자 공용 국가 시스템 → WOS는 대체 않고 **"양쪽 보고 일치 여부 점검·경고" 파수꾼**.
- 병원=양수보고, 리가메디=매출보고 → 둘이 맞물리는지 사전 대조 = 양쪽 모두에게 이득(행정 리스크↓).
- **NIMS는 향정 전용** → 매칭 현황판도 향정 전용. NIMS 데이터 **받아오기가 핵심.**
- 매칭 키: 거래일자+품목+lot+수량+거래처. 불일치 유형: 미보고·수량·lot·품목·중복·지연·반품역방향·폐기.

### 양수양도 워크플로우 (가볍게)
- 리가메디가 양수양도 처리 → 결과를 고객(병원)에게 **팝업으로 확인** → 끝.
- 실제 거래는 병원 이지스에서 발생 → 리가메디는 **병원 현재고 반영 여부만 판단.**

### 성분 기준 원칙 ★ (2줄 vs 합산 결론)
- 아빌리파이+아라빌(같은 아리피프라졸 2mg) 각 3000T → 합치면 6000T. **수요는 상품명이 아니라 성분 기준.**
- **2단 모델**:
  - 성분(generic) 레벨 = **수요·ROP·안전재고·발주 제안** (브랜드 무관 합산)
  - 상품·lot 레벨 = **재고·유효기간·반품·양수양도·폐기·NIMS** (브랜드·lot 특정 필수)
  - 듀얼코드/제조사 전환 = "한 성분 라인에 상품 2개"인 상태(별도 개념 아님)
- "상황 따라 다름": 합산이 기본, 의사 특정 브랜드 지정 등은 분리 가능.

## 7. NIMS 데이터 받아오기 — 조사 결과 (공개 자료)
1. **NIMS에 이미 "취급내역 불일치 조회" 존재**(2021~): 양수↔양도 등 한쪽 누락 감지. 단 "추정"이라 직접확인 필요, 사용성 나빠 약사회가 주1회 권고, 자기 것만 보임.
2. **연계 OpenAPI(dev.nims.or.kr) 존재**: 단 공개 API는 **품목·취급자 마스터 정보**만 명시, 연계는 **보고(push) 중심**. 거래내역 자동 pull API는 공개자료로 **미확인**(개발자센터 등록 후 확인).
3. **확실한 경로**: NIMS 화면에서 **보고내역·불일치 엑셀 다운로드** → WOS 업로드.
4. **2025-06-19 연계 제도화** → 빌드 시 식약처 SW검증·연계 신청 필요할 수 있음.

**함의**: NIMS가 이미 불일치를 잡으니 WOS는 중복 대신 **사전 대조 + 양방향 통합 + 보정 액션 관리**로 차별화. 입력 1차 = 리가메디 출고데이터(보유)+NIMS 불일치 엑셀, 2차 = 연계 API(규격 확인 후).

**사장님 확인 요청**
- NIMS "보고오류탐지결과→취급내역불일치건"에서 **엑셀 다운로드 되는지** 확인.
- 거래내역 pull API 여부는 빌드 단계에서 개발자센터 등록해 확인.
